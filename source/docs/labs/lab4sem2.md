Остальные модели справились заметно хуже:

5. KNN (0.5571) - ищет похожих соседей, но в таблицах с признаками разного масштаба и природы это даёт слабые результаты.

### 2. Почему не удалось получить ROC-AUC > 0.9
Достичь метрики выше 0.9 на этом датасете объективно сложно. Вот основные причины:

Ограниченный набор признаков. В таблице всего 10 базовых анкетных данных (возраст, доход, долги и т.п.). Нет истории платежей, транзакций или данных из бюро кредитных историй, которые критически важны для точного скоринга.
Модели уже выжали максимум. Деревья и градиентный бустинг отлично находят нелинейные зависимости в таблицах. Усложнение архитектуры (например, добавление нейросетей или увеличение глубины) на таком объёме данных приведёт не к росту качества, а к переобучению на шуме.
Природа финансовых данных. Поведение заёмщиков сильно зависит от внешних факторов (потеря работы, болезнь, макроэкономика), которых нет в датасете. Поэтому ROC-AUC ≈ 0.86 — это реалистичный и хороший результат для данной задачи.
### 3. План интеграции модели в веб-сервис
Шаги чтобы превратить обученную модель в работающий API (например, на FastAPI):
1. охранение артефактов. Упаковать модель и объекты предобработки в файлы через joblib. Добавить их в .gitignore. 
2. Структура проекта. Разделить код на логические модули: загрузка модели, валидация данных, маршруты API. Настроить виртуальное окружение.
3. Загрузка при старте. Загрузить модель в память один раз при запуске сервера, чтобы не тратить время на каждый запрос.
4. Валидация ввода. Описать схему ожидаемых JSON-данных (типы, обязательные поля, допустимые диапазоны), чтобы сервер сразу отклонял некорректные запросы.
5. Эндпоинт /predict. Создать маршрут, который принимает JSON, применяет предобработку, запускает модель и возвращает вероятность дефолта в формате JSON.
6. Надёжность. Добавить обработку ошибок, логирование запросов и написать тесты для проверки работы API.
7. Деплой и поддержка. Упаковать приложение в Docker-контейнер, выгрузить на сервер, настроить мониторинг и версионирование модели для будущих обновлений.
